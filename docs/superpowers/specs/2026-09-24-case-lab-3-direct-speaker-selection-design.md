# Case Lab 3: прямой выбор топ-3 на leaderboard

## Цель

Разрешить спикеру выбирать победителей прямо на странице `/live/leaderboard`, которая уже открыта на ТВ, без отдельной ссылки, кода или активации режима выбора в CRM.

## Зафиксированное поведение

- Страница `/live/leaderboard` продолжает показывать лидерборд и ответы участников.
- Когда выбранный вопрос находится в состоянии `shortlist_ready`, карточки его AI-shortlist становятся кликабельными.
- Спикер выбирает ровно три карточки, видит порядок выбора как места 1–3 и нажимает «Выбрать топ-3».
- После публикации используется существующий серверный переход в `awarded`; лидерборд и блок победителей обновляются через polling.
- Для вопросов, которые ещё не готовы к выбору, карточки остаются только для чтения.
- CRM сохраняет ручной fallback «Опубликовать топ-3» на случай, если выбор на ТВ не сработает.

## Серверный контракт

Публичный `POST /api/case-lab-3/live/selection` принимает только:

```json
{ "caseId": "<current-question-id>", "candidateIndexes": [0, 1, 2] }
```

`caseId` — идентификатор выбранного вопроса из уже публичной проекции leaderboard; это не идентификатор участника или ответа. `candidateIndexes` — позиции в shortlist, а не идентификаторы базы данных. Сервер:

1. Находит именно переданный live-кейс и проверяет, что он находится в состоянии `shortlist_ready`.
2. Загружает его включённые shortlist-записи.
3. Сортирует их так же, как публичная проекция: `final_order`, затем `ai_order`, затем `created_at`, затем `submission_id`.
4. Проверяет три уникальных индекса и преобразует их в `submission_id` только на сервере.
5. Вызывает существующий `publishLiveAwards`/RPC с местами 1–3.

Индексы имеют стабильный финальный tie-breaker по `submission_id`, поэтому позиция на ТВ совпадает с серверным сопоставлением даже при одинаковых порядках и времени создания. Токены спикера, query-параметры, fragment-параметры и `sessionStorage` для этого сценария удаляются. Это сознательная модель доверия для закрытого ТВ-экрана: любой посетитель, знающий URL, технически сможет отправить выбор, поэтому страница не должна считаться административной панелью.

## UI и ошибки

- В ответе leaderboard карточки содержат только полное имя и текст ответа.
- Режим выбора определяется состоянием вопроса, а не наличием токена.
- Одновременно можно отметить максимум три карточки; кнопка публикации активна только при выборе ровно трёх.
- При конфликте состояния показывается сообщение с предложением обновить экран.
- После успешной публикации выбранные карточки сбрасываются, а данные перечитываются.

## Область изменений

- Публичный API leaderboard и selection.
- Серверный live-репозиторий для разрешения позиций shortlist.
- Клиент leaderboard.
- Удаление CRM-кнопки отдельной ссылки; ручной fallback остаётся.
- Тесты API, публичной проекции и страницы.

Миграция базы данных не требуется.
